# 尾款解笼纪要（保证金笼）

- 纪要日期：2026-11-22（当日锁死，不得改口）
- 适用范围：本仓保证金笼，核验通过且已发生一笔部分拨付、仍留可用额的笼，其尾款拨付。
- 入口与会话：沿用 `POST /api/releases` 与既有登录会话/鉴权（admin、clerk 可写，viewer 只读），不新增入口、不换会话。
- 库文件：仍挂原处 `data/app.db`（SQLite，经 `db.DB_PATH` 定位），不新增库、不挪库。

## 一、正确性口径（二选一，已选定，禁止混用）

尾款拨付只允许在以下两条路径中选一条，全仓只能存在一种写法，两边不得混用：

- 甲路径（**本纪要选定并锁死**）：在**一笔提交事务**里完成
  1. 向正式拨付册 `releases` 写入尾款凭证（`status='已拨付'`，标记尾款）；
  2. 扣减笼可用 `cages.available`，尾款清零时笼状态置 `已解笼`；
  3. 同步减当事人账户 `bond_accounts.balance` 与 `bond_accounts.frozen`（资金真实出系统）；
  4. 写审计 `audit_trail`。
  任一步失败，整笔事务回滚：拨付册与扣减一并撤销，笼面、账户零改。
- 乙路径（**禁用**）：先落影子拨付单据、再原子晋升进正式拨付册并切笼面账户；失败则单据作废、正式拨付册与笼面零改。

### 偏离处置

- 禁止只改解笼页提示而不落真实扣减。
- 代码侧以 `release_svc.TAIL_POLICY_LOCKED` 固化本纪要选择（`path='甲'`、日期 2026-11-22、禁影子）。
- 任何检测到影子表/晋升式尾款写法，或策略常量与本纪要不一致的写入请求，记 **尾款偏航**（审计动作 `cage_tail_yaw`）并拒写（HTTP 409，detail 含「尾款偏航」），不产生任何业务数据改动。

## 二、并发口径

- 两人同时清同一笼尾款，须抢同一把笼锁 `cage:{cage_id}`（沿用 `cage_locks`/`contention_log` 公共并发面）。
- 先到者持锁完成尾款事务；后到者抢锁失败，**只留争用痕**（`contention_log` 一行，action=`争用`），不写任何业务数据，返回 409。
- 争用痕必须在独立提交中持久化，不得被业务事务回滚带走。

## 三、五页同源

解笼页、入笼页、账户页、对账页、审计页五页账实同源，统一以 `data/app.db` 同一份库表经既有 `/api/*` 只读接口取数，禁止页面私有账外口径：

- 笼面：`cages.available/status`；
- 拨付册：`releases`（尾款以 `is_tail=1` 标识）；
- 账户：`bond_accounts.balance/frozen`；
- 对账：`reconcile_svc` 以 `available + 已拨付 + 已罚没 == amount`（同笼代）核算，并核 `account.frozen == 活笼可用合计`；
- 审计/争用：`audit_trail` / `contention_log`。

## 四、验收口径

1. 先备「部分解笼后仍留可用额」的种子事故夹具（`fixtures/tail_incidents.json`，独立当事方与笼，含一笔已拨付部分款与通过核验）。
2. 先落两条失败测并确认见红，才准改服务：
   - 尾款未扣额失败测（凭证之外，笼可用、账户余额/冻结必须真实扣减，尾款清零、对账平衡）；
   - 双人同清尾款争用失败测（后到 409、只留争用痕、业务零写）。
3. 禁止跳过失败测，禁止无测直线改文案。
4. 尾款清零后对账平衡；夹具在本机文件库（`data/app.db`）跑通。
